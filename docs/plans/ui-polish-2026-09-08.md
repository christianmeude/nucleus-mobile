Status: PLANNING (not yet implemented)

## Context

NUcleus mobile (`nucleus-mobile`) — research repository for NU-Dasmariñas.
This plan covers a batch of layout, consistency, and design-system polish
requests raised after the faculty/research detail work landed. All decisions
below were confirmed with the user on 2026-09-08.

Key groundwork already established:

- The app is font-consistent: **Inter** everywhere (via `@expo-google-fonts/inter`),
  loaded in `App.tsx`, resolved through `theme/typography.ts` → `families` (ui + display

  runtime inconsistency).

- Category colors in RN are naval shades; web project uses a diverse palette.

## Task 8 — Fix stale font docs (EASY, do first)

### Problem
`DESIGN.md` typography block and prose, plus `PRODUCT.md`, reference **Roboto**.
The codebase resolves every font through Inter. The user perceives inconsistency
because the spec contradicts the shipped typeface — but there is no runtime
inconsistency.

### Change
- `DESIGN.md`: replace all "Roboto" references with "Inter" (front-matter
  `typography` block, "One Typeface" narrative, "Display/Body Font", all token
  `fontFamily` values, and "Single Font Rule" wording).
- `PRODUCT.md`: no explicit font claim found, but verify. If present, align to Inter.
- Leave `theme/typography.ts` untouched (already correct).

### Verification
- Grep confirms zero "Roboto" in repo (except screenshots/assets).
- `npx tsc --noEmit` still clean.

## Task 6 — Stabilize notification badge (TopBar)

### Problem
`src/components/ui/TopBar.tsx` — the bell container uses
`actions: { position: 'absolute', right: 0, top: 0, zIndex: 10 }` (lines 166-175).
Absolute positioning pins the bell to the top of the row, so its vertical center
tracks the left content's height. On Browse (bare `TopBar`, 44px row) the bell
sits lower than on MyPapers/FacultyReview (taller rows with title+subtitle). The
badge appears to "shift" across screens.

### Change
- Convert `actions` from `position: 'absolute'` to a normal flex child:
  `flexDirection: 'row', alignItems: 'center', justifyContent: 'flex-end',
  gap: sm, flexShrink: 0`.
- Remove `position`, `right`, `top`, `zIndex` (no longer needed; the bell centers
  in the row via `alignItems: 'center'` on `row`).

### Files
- `src/components/ui/TopBar.tsx` (actions style only)

### Verification
- Bell badge is vertically centered relative to left content on Browse, MyPapers,
  FacultyReview, and both DashboardHero variants.

## Task 7 — Browse header parity with Papers

### Problem
- `MyPapersScreen.tsx`: raised header wrapper (`surface.raised`, `borderBottom`
  hairline, `zIndex: 10`), `TopBar variant="compact"` with "My Papers" title +
  subtitle, then SearchField + SegmentedControl (lines 244-270, styles 345-353).
- `FacultyReviewScreen.tsx`: same pattern with "Review Queue" (lines 161-185).
- `BrowseScreen.tsx`: bare `<TopBar />` (no title, no children, line 363) over a
  plain `root` view with no raised header, then `BrowseHeader` (search + filter).

### Change
- Wrap Browse's `TopBar` + `BrowseHeader` (search) in a raised header wrapper
  mirroring MyPapers: `paddingHorizontal: lg`, `paddingTop: xl`, `paddingBottom:
  sm`, `gap: md`, `backgroundColor: surface.raised`, `borderBottom` hairline,
  `zIndex: 10`.
- Give `TopBar` a title **"Browse"**. Prefer `children` block (title + optional
  result-count subtitle) to match MyPapers' title+subtitle composition, OR use the
  `title="Browse"` prop if no subtitle is desired. Confirm subtitle content with
  user if adding one.

### Files
- `src/screens/main/BrowseScreen.tsx` (structure lines 354-411, styles)
- Possibly `src/screens/main/browse/BrowseHeader.tsx` (adjust padding if header
  wrapper now owns horizontal padding — avoid double gutters)

### Verification
- Browse and MyPapers look like sibling list screens; same raised header language.

## Task 5 — Category colors match web

`brand.primary` (#1B3A8C), `navy[300]` (#5F7EC9), `navy[400]` (#2E5BC9),

313-327) uses diverse gradients by index.

colors, since RN uses them as dot/accent, not gradients):

| 1 | `#578FCA` → `#3674B5` | `#578FCA` |
| 2 | `#3674B5` → teal | `#14B8A6` |
| 3 | green → emerald | `#22C55E` |
| 4 | amber → orange | `#F59E0B` |
| 5 | red → pink | `#EF4444` |
| 6 | teal → green | `#14B8A6` |
| 7 | `#3674B5` → cyan | `#06B6D4` |

Fallback: `#6B7280` (web gray), replacing the current `brand.primary` fallback.

### Files

## Task 3 — ResearchDetail layout (prototype 3 options; NO section dividers)

### Problem
`ResearchDetailScreen.tsx` is a single continuous scroll of 10+ flat sections:
category/badge → title → authors → affiliation → meta → feedback → DOI →
bookmark → paper preview → keywords → abstract → related → review progress.
Everything has equal visual weight; no grouping.

### Approach
Build **three toggleable layout variants** (user chose to prototype card grouping,
tabbed/segmented, **and one more**, but explicitly excluded "section dividers").
Ship all three behind an easy switch so the user can A/B on device, then pick one.

### Option A — Card grouping
Group related content into raised `Card` surfaces:
- **Header card**: category+badge row, title, authors, affiliation, meta row,
  feedback row (bookmark action right-aligned in header card).
- **Paper card**: the existing PDF preview (already card-shaped).
- **Details card**: keywords + abstract.
- **Related card**: related-papers list.
- **Progress card**: review workflow.
- DOI + publication request stay standalone cards (they already read as cards).

### Option B — Tabbed/segmented
- Sticky top block: title, authors, affiliation, meta (always visible).
- `SegmentedControl` (matches MyPapers component): **Overview | Paper | Reviews**.
  - Overview: DOI, keywords, abstract.
  - Paper: PDF preview + "View Full Paper".
  - Reviews: feedback row, related papers, review workflow.

### Option C — Sticky header + reveal (the "one more")
- Fixed/sticky header region: category + badge, title, authors — always visible
  (mimics iOS large-title collapse).
- Scrollable body keeps grouped sections with varied spacing (tight within groups,
  generous between), no flat dividers.

### Files
- `src/screens/main/ResearchDetailScreen.tsx` (refactor JSX + styles)

### Verification
- All three compile; user toggles between them on device and selects one. Only the
  chosen variant ships; others removed.
