# GitHub Milestones Convention

## Milestone description template

Use one paragraph in this pattern: summarize the scope in one sentence, state total phase count, call out which issues were resolved or mitigated, and close with notable technical outcomes (for example architecture decisions, validation results, or constraints preserved).

## Example: UI Overhaul Complete (Milestone #2)

10-phase UI overhaul completed across design tokens, shared components, main screens, accessibility polish, and validation; Issue #4 was resolved and Issue #8 was mitigated in UI pending backend `allow_download` support. Notable outcomes include a frozen-layer clean diff against `origin/dev`, Android-safe `ResearchDetail` header handling under edge-to-edge, and a fully passing smoke-test checklist before merge.

## Milestone policy

Milestones are for grouped, closed delivery work. Deferred or still-open items usually remain un-milestoned until active, or are assigned to a clearly scoped future milestone once execution starts.
